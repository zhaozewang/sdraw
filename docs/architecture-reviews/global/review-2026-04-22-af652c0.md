### F-001 — Undocumented repo-level intent  ·  severity: **high**  ·  effort: one-pr

The repo has no root `CLAUDE.md`, no `docs/architecture.md`, no `.claude/rules/`,
no `docs/adr/`. Evidence: `ls -la` of `.` and `.claude/` produced
no such files.

Consequence: A repo-root architectural review has no ruler. The only
cross-subsystem invariants available are the ones in the README (which has
drifted) and the one subsystem skill (`board-kernel`). Everything outside the
board-kernel subsystem — autosave, board file format, cache layout, watcher,
export, VS Code bridge, electron packaging — has no stated intent to measure
code against.

Recommended fix: draft a root `CLAUDE.md` listing (a) the top-level
contract of each subsystem in ≤ 5 lines, (b) the data-flow from .sdraw file →
board store → canvas → autosave → disk, (c) load-bearing invariants already
discovered in handoff docs (e.g. "autosave path is the render guarantee; do not
refactor", "element crop coordinates are image-relative, not viewport-relative",
"legacy subprocess plot path must remain as fallback when `board_id` is absent").

`README.md:90-119` describes a tree that no longer exists:

  Reality also has `ExternalChangeModal.tsx`, `PlotEditor/`, `PythonEnvPicker/`,
  `Settings/`, `SetupEditor/`, `shared/` — the entire plot-editor modal + setup

- Feature list omits: per-board Python kernel + shared setup, multi-figure plots,
  Run All, Run Setup, pen/freehand drawings, external-change detection,

Fix shape: rewrite `## Architecture` against the current file list; move the
detailed tree into `docs/architecture.md`; keep README to a 10-line high-level

### F-005 — `Board` Pydantic model missing `autoExport` field  ·  severity: medium  ·  effort: one-pr

`backend/models/board.py:135-147` declares `Board` with fields
`schema_version, id, name, canvas, elements, setup, plotCodes, created_at,
updated_at, app_version, thumbnail`. The frontend writes `board.autoExport`
(`frontend/src/types/board.ts:140`), and the delta-save path stores it:
`backend/routers/boards.py:242, 299-300` accepts `auto_export` and writes
`existing["autoExport"]`.

But `PUT /api/boards/{board_id}` (`backend/routers/boards.py:141`) validates
through the strict `Board` model, which means it silently drops `autoExport`
on any full-replacement write. Same for anything that calls
`ws_service.save_board(board)` on a workspace-stored board.

File-based `POST /api/boards/save` takes a raw dict so it's unaffected; that's
the path the app actually uses. But if/when workspace-storage boards get
re-enabled, autoExport will vanish on first PUT.

Fix shape: add `autoExport: Optional[AutoExportSettings] = None` to `Board`,
plus the nested `AutoExportSettings` model matching
`frontend/src/types/board.ts` AutoExport shape.

### F-006 — Monolithic frontend files hiding subsystems  ·  severity: medium  ·  effort: phased-refactor

- `frontend/src/store/boardStore.ts:1-2125` bundles: board open/save/close,
  element CRUD, group/align/z-order, history/undo, autosave dirty tracking,
  kernel actions, multi-figure distribution, Run All, auto-export, external
  conflict resolution, figure-ghost preview, VS Code bridge responses.
- `frontend/src/components/PlotEditor/PlotEditor.tsx:1-1439` bundles the modal,
  CodeMirror wiring, setup tab, figure thumbnail strip, run cache keyed by
  plotCodeId (`:442-697`), sibling code resolution.
- `frontend/src/components/Inspector/Inspector.tsx:1-1417` bundles every
  per-element-type property editor.
- `frontend/src/App.tsx:1-1412` is an app shell + home screen + routing + board
  view + SetupEditor mount + beforeunload beacon.

These are all quantitative smells only — no behavior bug — but they're the
places where future review runs will miss real drift because the files are too
large to audit cheaply. No intent doc sets a LOC budget, so this is a
`convention-gap`, not a `rule-violation`.

Fix shape: draft an ADR "large files are allowed but the following subsystems
MUST be in their own file: `autosave`, `history`, `kernelActions`,
`multiFigureDistribution`, `runAll`, `externalConflict`." Then split boardStore
behind that rule rather than refactoring first and codifying later.

### F-007 — Legacy subprocess plot path retained with partial parity  ·  severity: low  ·  effort: one-pr (doc)

`backend/routers/plot.py:78-109` routes kernel-capable requests via
`kernel_manager.exec_plot` when `board_id` is set; everything else falls
through to `plot_runner.py` (`:138-225`). The skill doc
(`.claude/skills/board-kernel/SKILL.md:167`) states:

> The legacy subprocess path still exists... Don't delete it — developer
> scripts, VS Code extension paths, and some tests rely on it. It does NOT
> do project-root resolution, so callers stuck on the legacy path lose that
> benefit.

Grep shows no VS Code extension or test still uses the legacy path for
production behavior:
- `vscode-sdraw/src/*.ts` does not call `/api/plot/execute` at all.
- `backend/tests/*.py` only tests `kernel_manager` and `kernel_runner`, not the
  `/api/plot/execute` HTTP surface.

So the stated reason ("VS Code / tests rely on it") no longer holds; the only
real consumer is the board-less developer scratchpad case (if any). Either
delete the legacy path and its 60 lines of env/subprocess wiring in `plot.py`,
or update the skill doc to say "legacy path kept for board-less `/execute`
callers only; all board-backed runs go through the kernel."

### F-008 — No test coverage for the board-file layer or any frontend code  ·  severity: medium  ·  effort: phased-refactor

Feature inventory (below) shows 34 user-visible features; only 2 have unit
coverage (the kernel setup/plot protocol and the kernel manager's session
handling). Everything else — schema migration, delta save merge semantics,
`save_cache` authoritative-ids logic, checkpoint recovery, gzip request
decompression, file watcher WebSocket fan-out, every frontend store action,
every React component — is flying blind.

Evidence: `backend/tests/` contains exactly `test_kernel_manager.py` (13 tests)
and `test_kernel_runner.py` (13 tests). `find frontend -name '*.test.*'`
returns nothing.

Fix shape: scope this to a phased plan. Priorities (in order of blast radius):
1. `backend/services/board_cache.py::migrate_board_schema` + `save_cache`
   authoritative-ids logic — the recent "stale plotly data for months" comment
   (`:126`) shows this is hard to get right by hand.
2. `backend/routers/boards.py::save_board_delta` — the merge logic is
   non-trivial and owns every subsequent write.
3. One component test for `boardStore.distributePlotFigures` — the
   multi-figure logic is the single most bug-prone path in the frontend
   (per commit history).

This becomes `test_coverage_gap` findings in the per-subsystem reviews that
come next.

### F-009 — Frontend `CURRENT_SCHEMA_VERSION` defined in two places  ·  severity: low  ·  effort: one-pr

`backend/services/board_cache.py:26` sets `CURRENT_SCHEMA_VERSION = 3`.
`frontend/src/types/board.ts:123` sets `export const CURRENT_SCHEMA_VERSION = 3`.
Both need to be bumped together when the schema evolves, and nothing tests that
they stay in sync. Either fetch the version from a single source (ship a tiny
`/api/schema` endpoint, or codegen the frontend constant), or add a test that
asserts equality.
