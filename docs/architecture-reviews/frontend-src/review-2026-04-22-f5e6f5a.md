  `docs/architecture.md`.
- The only cross-frontend written artifact is the drifted README tree
  (`README.md:90-119`, global F-002).

Nothing about the cleanup stream changes this finding. Phase 2-4
specifically DID codify module-level conventions in their SKILL.md
files (e.g. `frontend-cleanup-phase-4-welcome-screen-extract/SKILL.md`
describes the screens/ layout), but SKILL.md files are planning
artifacts that are consumed once — they're not the durable ruler
this scope needs.

The reason this keeps mattering: every surviving finding below
(FS-002, FS-003', FS-004, FS-008') is really a rule-that-isn't-written
problem. A one-page `frontend/CLAUDE.md` fixes the enforcement gap for
all four at once.

Recommended content (unchanged from prior review):
(a) module map of the 43 files grouped by responsibility;
(b) rule "state reads flow through subscription; `getState()` is
allowed only inside store actions, event handlers, timers,
`useEffect` cleanup, and imperative DOM";
(c) pointer to `.claude/skills/board-kernel/SKILL.md` for the kernel
protocol;
(d) list of 4-5 load-bearing invariants currently hidden in comments
(plotCodeId registry; autosave = render guarantee; delta save
suppresses checkpoint when snapshot exists; figure anchor convention);
(e) a module budget — "files over N LOC must be split or have an
ADR explaining why they're not" — so FS-002 has a ruler to measure
against.

Cite: `frontend/` (0); `frontend/src/` (0); `README.md:90-119`.

### FS-010 — Wider `localStorage`-without-accessor gap (successor to FS-008)  ·  severity: low  ·  effort: one-pr  ·  **new**

FS-008 scoped to four keys (recent-boards, theme, python-env,

| File | key(s) | call-sites |
|---|---|---|
| `components/Settings/Settings.tsx:56-91` | `sdraw_default_grid_size`, `sdraw_default_snap`, `sdraw_default_grid`, `sdraw_default_canvas_w`, `sdraw_default_canvas_h`, `sdraw_default_export_dpi`, `sdraw_default_export_format` | 14 (7 get + 7 set) |

| `components/Canvas/Canvas.tsx:362, :1012` | `sdraw_viewport:${path}` (per-board dynamic key) | 2 |
| `components/PythonEnvPicker/PythonEnvPicker.tsx:61, :64, :73` | `RECENT_ENVS_KEY = 'sdraw_recent_python_envs'` | 2 |

All have the same issues the original four had: string-literal keys
(or local consts that aren't shared), no type guards, no parse-failure
recovery, no central schema.

The dynamic-key case (`sdraw_viewport:${path}`) is a new shape the
`localStorage.ts` API doesn't cover yet — it needs a namespaced
accessor pattern (`getViewport(boardPath)` / `setViewport(boardPath,
state)`).

Recommended fix: extend `utils/localStorage.ts` with two new sections:
(a) Settings defaults (8 typed accessors — one per key, or a grouped
`getSettingsDefaults()` / `setSettingsDefaults()`); (b) per-board
viewport (namespaced). Move `LAST_DIR_KEY` / helpers.ts access in too.
Move `RECENT_ENVS_KEY` out of PythonEnvPicker component.

This is the natural Phase 5 localStorage follow-up.
